The deterministic / probabilistic split (the Riyadh winning pattern)

Probabilistic AI (kb/store.py retrieval, agents/gap_analyzer.py LLM) only retrieves and proposes. Deterministic software (guardrails/compliance_checker.py, rules R1–R7 in pure Python) governs: it computes the verdict, and no LLM output can change it. Every LLM finding must carry a verbatim_quote verified by substring match against the retrieved chunks, or it is downgraded to INSUFFICIENT_EVIDENCE. When the knowledge base has no relevant policy, the verdict is NEEDS_REVIEW — the system refuses to invent compliance.

📥 Data flow (one evaluation)

  • SRC → C → PP: 22 policy documents loaded, chunked, embedded (ONNX MiniLM-L6-v2, CPU).
  • M: semantic retrieval (top-k chunks) + LLM gap analysis with quote verification.
  • P: 7 deterministic rules evaluated with word-boundary matching and negation handling.
  • D → SINK: cited verdict assembled; every stage audit-logged under a unique run_id.

🎯 AI Readiness Framework perspectives reflected

  • Human supervision: R1/R6 require meaningful human oversight; no AI-only high-stakes decisions.
  • Contextualization: UAE corpus (MoE, TDRA, AI Strategy 2031) as primary layer; UNESCO/OECD/EU as global reference.
  • Policy opportunity identification: gap findings surface where UAE guidance is silent vs. global practice.
  • Open source: MIT-licensed public repo, CI-tested, auditable JSONL trails.
